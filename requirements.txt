# What the *service* needs to answer a request, and nothing else.
#
# This file is the container's dependency set: docker/Dockerfile installs it and
# nothing more, which is most of how the runtime image stays under 2 GB. Test,
# lint and dataset-acquisition tooling lives in requirements-dev.txt, which
# includes this file — so `pip install -r requirements-dev.txt` (what `make
# setup` does) still gives a developer everything, and the split costs nobody
# an extra step.
#
# Two things here are *not* pinned in this file and matter more than anything
# that is: the container installs torch and torchvision from PyTorch's CPU wheel
# index first, so the CUDA build's ~2.7 GB of bundled nvidia libraries never
# lands in the image. See the note in docker/Dockerfile.

# Core anomaly detection
anomalib
torch
torchvision
onnxruntime

# CLIP backbone for WinCLIP (anomalib's `clip` extra). The upper bound is
# anomalib's own and it is load-bearing: from 2.26 open_clip's transformer
# stack became batch-first, while anomalib's WinCLIP still permutes to
# length-first before calling it by hand. The mismatch raises nothing — every
# sliding window pools to the same vector, so the anomaly map comes back
# perfectly uniform and the model looks merely bad rather than broken.
open-clip-torch>=2.23.0,<2.26.1

# API / serving
fastapi
uvicorn[standard]
pydantic>=2.0

# Vision / numerics
#
# `-headless` rather than plain opencv-python, for two reasons. It is the build
# anomalib itself depends on, and installing both puts two packages in the image
# that each own the `cv2` import name — whichever pip unpacks last wins, which is
# not a thing to leave to chance. And the GUI build links libGL, which
# python:3.11-slim does not ship: the non-headless wheel turns `import cv2` into
# an ImportError inside the container unless ~100 MB of X11 libraries are
# installed to satisfy an interactive window nobody can see. Nothing in this
# repo calls cv2.imshow; the plots are matplotlib's.
opencv-python-headless
numpy
scikit-learn
# Declared explicitly rather than leaned on as a scikit-learn transitive: this
# project imports it directly for `ndimage` (AU-PRO's connected-component
# labelling) and `stats.ks_2samp` (the drift test), and a dependency you import
# is a dependency you pin.
scipy
matplotlib
Pillow

# Model-hub client. Runtime, not tooling: WinCLIP's backbone weights are fetched
# through it on first use, which is what makes the zero-shot backend work in a
# container with no checkpoint mounted.
huggingface_hub

# Observability
prometheus-client
structlog
opentelemetry-sdk
opentelemetry-api

# OTLP span export, needed only when OTEL_EXPORTER_OTLP_ENDPOINT points at a real
# collector. The SDK does not pull it in, and the default ConsoleSpanExporter
# needs nothing, so it is left commented rather than adding ~10 MB of protobuf
# machinery to every install. app/observability/tracing.py degrades to the
# console exporter with an ERROR log if an endpoint is set without this present —
# a missing telemetry dependency must not stop an inspection line from answering.

# Infra
#
# redis backs app/serving/model_cache.py, which remembers which models were
# loaded so a restarted API can rebuild its working set. It is optional at
# runtime — the cache degrades to an in-process dict — but the client is a
# declared dependency rather than an optional import, because "the feature is
# off because a package is missing" is a worse failure than any it prevents.
redis
python-dotenv
